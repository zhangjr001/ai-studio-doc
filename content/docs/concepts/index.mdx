Spark AI Studio 采用结构清晰的分层对象模型。理解这些概念之间的隶属与协作关系，能够帮助你在构建复杂 AI 业务流时迅速理清思路。

![组织与多项目层级结构](/images/overview/organizations.png)

## 1. 租户与空间模型

平台采用 **平台控制台 → 组织（Organization） → 项目（Project）** 的三层层级模型：

```
Platform Console (全平台管控)
  └── Organization 1 (团队/租户空间)
        ├── Project A (营销助手)
        ├── Project B (知识检索中心)
        └── Project C (自动化客服)
  └── Organization 2 ...
```

### 组织（Organization）
- **边界范围**：组织是团队成员身份与计费/资源配额的隔离边界。
- **权限角色**：
  - `Owner`：拥有组织全部权限，包括转让、解散组织与全量项目管理；
  - `Co-owner`：拥有组织管理权限，包括成员邀请、项目增删与组织级设置；
  - `Member`：普通成员，可访问分配给其的具体项目。

### 项目（Project）
- **边界范围**：项目是具体业务场景的工作空间，属于核心资产聚合单元。
- **包含资产**：
  - **工作流（Workflows）**：业务编排拓扑；
  - **提示词（Prompts）**：团队沉淀的可复用系统提示词库；
  - **知识库（Knowledge Bases）**：挂载的向量化与全文检索数据源；
  - **MCP 工具（MCP Tools）**：知识库派生的检索工具与外部接入工具；
  - **向量查询（Vector Query）**：调试与验证多知识库检索效果的沙箱；
  - **项目设置（Settings）**：独立的 API 密钥、模型通道配置与全链路追踪配置。

## 2. 工作流与智能体模型

工作流采用基于有向无环图（DAG）的可视化编排范式，核心构成包括：

```
[Start 节点] ──> [Rule Guardrail 安全护栏] ── pass ──> [Agent 智能体] ──> [Router 路由] ──> [End 节点]
                                     │
                                    fail ──> [拦截结束/告警]
```

### 节点类型与分类
1. **控制类（Control）**：
   - `START`：工作流起始节点，定义外部调用所需的输入变量 Schema（如 `input: string`）；
   - `END`：工作流终点节点，汇总并标准化最终向用户或调用方返回的数据；
   - `ROUTER`：条件分流节点，根据上游执行结果字段（如 `{{ node.agent-xxx.output.answer }}`）或自定义表达式进行动态下游分支路由。
2. **智能体类（AI）**：
   - `AGENT`：执行 LLM 推理的核心智能体。可配置推理模型、绑定提示词资产、勾选 MCP 工具、开启会话上下文记忆，并定义输入/输出变量映射。
3. **安全防护类（Safety）**：
   - `RULE_GUARDRAIL`：确定性规则护栏。支持最大文本长度限制、敏感个人隐私信息（PII，涵盖中国手机号、身份证、车牌号、VIN车架号、电子邮箱）过滤、提示词注入与越狱检测以及自定义正则表达式。具备 `pass` 和 `fail` 双分支。
   - `LLM_GUARDRAIL`：基于大模型的语义判断护栏。通过专门的判定提示词对复杂意图或内容合规性进行语义打分与分支导流。

### 草稿与版本发布生命周期
- **草稿态（Draft）**：在画布上的每一次节点调整、参数修改与连线变动均处于草稿状态，保证编辑过程中的改动不会影响线上正在调用的生产实例；
- **发布态（Published vX）**：点击「发布」后，系统生成当前工作流的不可变版本快照（如 `v1`, `v2`, `v3`），并通过统一开放 API 供业务系统稳定调用。

## 3. 知识库与数据流水线 (RAG)

知识库负责将企业的非结构化多模态文档转变为智能体可精确检索的动态知识源：

```
文档上传 ──> 格式检测与解析 ──> 文本清洗 ──> 块切分(Chunking) ──> 向量化(Embedding) ──> 混合索引库
  PDF/Word/PPT/Excel/MD/TXT         去噪/过滤      大小/重叠窗口           Dense Vector          KNN + BM25
  图片(OCR-VL) / 音频(Whisper)
```

- **解析能力**：涵盖纯文本、各类 Office/PDF 文档，以及通过多模态视觉模型（OCR-VL）解析的图片扫描件，通过 Whisper 转写的语音记录；
- **检索架构**：支持稠密向量（Dense KNN）与全文倒排索引（BM25）协同运行，结合倒数排名融合（RRF）算法实现高质量语义与精准关键词的平衡检索。

## 4. Model Context Protocol (MCP) 模型上下文协议

AI Studio 深度拥抱开放标准 Model Context Protocol（MCP），在架构中兼具两重身份：

1. **MCP 工具提供者（MCP Provider）**：
   - 自动将项目中的知识库封装为标准的 MCP 检索工具（支持 `_HYBRID`、`_TEXT`、`_KNN` 模式）；
   - 对外暴露标准的 `/api/v1/mcp` 端点，允许外部 MCP 客户端（如 Cursor、Claude Desktop 等）零代码挂载企业知识。
2. **MCP 工具使用者（MCP Consumer）**：
   - 支持通过 HTTP 或 Server-Sent Events (SSE) 协议注册外部远程 MCP 服务的工具；
   - 外部工具直接注册进工作流的 Agent 节点中，使智能体具备查询实时业务数据库、操作外部 API 的能力。

## 5. 提示词资产工程

提示词不再散落于代码或单个节点中，而是作为项目一等公民进行集中化治理：

- **版本不可变性**：每次修改均自动创建新版本（`v1`, `v2`...），历史版本只读保存，便于回滚与审计；
- **反向引用拓扑**：提示词详情页实时追踪当前版本正在被哪些工作流的哪些智能体节点引用，杜绝无意变更导致线上工作流异常。

---

## 6. 全链路追踪与观测 (Observability)

在企业级交付场景中，全链路可视化至关重要：
- **OpenTelemetry 标准**：后端工作流执行引擎原生集成 OTel 标准 Span 追踪；
- **Langfuse 深度集成**：工作流执行的每一步（节点跳转、Prompt 插值、LLM 耗时、Token 统计、Guardrail 判定）均自动上报至项目绑定的 Langfuse 实例，支持在调试抽屉中直接点击查看单次调用的完整 Trace。
