检索质量决定了 RAG 效果的上限。AI Studio 的检索层支持向量与全文两种召回方式，并可用重排模型精排。

## 检索流程

```
用户查询
  ├─ 向量召回：查询向量化 → 与 chunk 向量做相似度检索
  └─ 全文召回：关键词匹配
        ↓
  合并去重（可选 Rerank 重排）
        ↓
  Top-K 结果注入 LLM 上下文
```

## 可调参数

| 参数 | 说明 | 建议值 |
| ---- | ---- | ------ |
| Top-K | 最终注入上下文的块数量 | 3–10 |
| 召回数量 | 重排前候选集大小（应大于 Top-K） | Top-K 的 3–5 倍 |
| 相似度阈值 | 过滤低相关结果 | 0.3–0.5（视模型而定） |
| 重排 | 是否启用 Rerank 模型精排 | 追求精度时开启 |

## 检索测试

知识库详情页提供**检索测试**（Retrieval Test）：

1. 输入一条典型用户问题；
2. 查看命中的 chunk 内容、来源文档与相似度得分；
3. 命中不理想时，对照调整分块参数或召回参数，迭代验证。

<Callout type="tip">
  建立一套固定的测试问题集（10–20 条真实业务问法），每次调整参数后全量跑一遍，避免「调好一条、弄坏一片」。
</Callout>

## 在工作流中引用

知识库检索节点的输出包含命中块列表，可在下游 LLM 节点的提示词中通过 `{{检索节点.results}}` 引用，并按需控制注入格式（如拼接来源标题）。
