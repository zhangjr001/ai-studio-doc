在真实生产应用中，仅依赖向量相似度或仅依赖关键词匹配往往无法兼顾「语义泛化理解」与「专有名词/精确型号匹配」。Spark AI Studio 提供了工业级的混合检索架构与全方位的调试沙箱。

![文档级检索测试沙箱](/images/knowledge/document-retrieval-test.png)

## 三大检索模式

系统针对不同业务偏好，在底层封装了三种标准的检索策略：

| 检索模式 | 技术方案 | 适用典型场景 | 优劣势比对 |
| -------- | -------- | ------------ | ---------- |
| **`HYBRID`（混合检索）** | 向量语义（KNN） + 关键词倒排（BM25），采用 **RRF（倒数排名融合）** 算法合并评分 | **推荐首选**。既有模糊意图提问，又包含具体产品型号、错误码的综合查询 | 召回最均衡、抗噪能力最强，但兼具模型调用与分词计算 |
| **`KNN`（向量检索）** | 仅使用文本嵌入向量计算余弦相似度（Cosine Similarity） | 用户口语化表达、自然语言多轮意图匹配、语义改写问答 | 善于理解上下文内涵；对生僻型号、数字序列或缩写容易出现幻觉漏检 |
| **`TEXT`（全文检索）** | 仅基于分词器与 BM25 频率统计进行匹配 | 明确的产品型号（如 `W213`）、零件序列号、法规条款编码等 | 精确度极高、零向量模型开销；无法理解近义词与同义表述 |

## 调试与验证沙箱

为了确保知识切块的召回准确率，AI Studio 提供了两个维度的验证工具：

### 1. 单文档检索验证（Document Test）
在知识库详情页的文档列表点击 **测试** 按钮，系统会弹出该文档专属的检索测试窗口：

![文档快速检索测试弹窗](/images/knowledge/document-retrieval-test.png)

- 输入拟真的测试问题（例如 `车钥匙有几种按键功能？`）；
- 系统在当前单个文档内切块中快速跑一遍相似度计算，展示命中的 Chunk 内容及得分；
- 便于快速验证分块大小是否合理、关键信息是否被截断。

### 2. 项目级「向量查询」工具（Vector Query）
进入项目侧边栏的 **向量查询**（`/project/:id/search`）模块，这是一个跨知识库的全局调试沙箱：

![向量查询跨知识库全局调试沙箱](/images/search/vector-query-ui.png)

- **知识库范围多选（Scope）**：在左侧面板自由勾选一个或多个知识库（如同时勾选 `1030` 和 `aa`），模拟多知识源协同召回；
- **检索模式切换**：支持在输入框右侧下拉菜单自由选择 `HYBRID`、`KNN` 或 `TEXT`；
- **Top-K 控制**：自由指定召回的片段上限（如 `Top 3`、`Top 5`、`Top 10`）；
- **执行查询**：点击「查询」后，界面直接以卡片形式展示召回片段的正文内容、所属文档名、Page 页码与综合相关度得分。

<Callout type="tip">
  如果测试查询时出现服务异常，请先到「项目设置 → Models」检查是否已为当前项目添加并配置了可用的 **向量化模型（Embedding）**。未指定嵌入模型时，向量计算无法完成。
</Callout>

## 在工作流中调用知识库

AI Studio 不强制使用孤立的检索节点，而是通过先进的 **MCP（Model Context Protocol）** 将知识库封装为标准的检索工具。

在编排工作流时，只需在 Agent 节点的「工具（Tools）」配置中勾选对应的知识库检索工具（如 `kb_1030_5e1ff052_HYBRID`），大模型即可在与用户交谈过程中，根据实际问题自主决定何时调用该工具查询知识，并将召回的权威内容作为上下文生成精准回答。
