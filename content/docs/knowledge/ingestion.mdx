知识库的高质量检索离不开底层的入库处理管线。Spark AI Studio 在统一后端嵌入了强大的文档解析与分块管道，保证各类非结构化文档能够高效转换为高质量的语义切块。

![知识库文档分块与清洗控制台](/images/knowledge/knowledge-base-detail.png)

## 完整入库处理流水线

当用户将文档上传至知识库后，系统将自动触发异步处理作业：

```
[文件上传] ──> [格式识别与路由] ──> [多模态内容抽取] ──> [规则文本清洗] ──> [语义分块] ──> [并发向量化] ──> [混合索引落库]
                     │                    │                   │               │               │               │
                 类型安全校验         OCR / Whisper       去噪/正则清洗    Size/Overlap   Embedding API    KNN+BM25
```

---

## 阶段详解

### 1. 格式识别与抽取引擎
根据文件扩展名与二进制 Magic Number 自动调度不同的抽取引擎：
- **办公文档（PDF / DOCX / PPTX / XLSX）**：通过内置解析引擎提取正文、表格与段落层级，尽可能保留文档的标题结构；
- **纯文本与轻量标记（TXT / MD）**：直接以原生字符流快速加载；
- **图像与扫描件**：自动路由至项目配置的 **多模态模型（OCR-VL）**，识别图文混排的图片内容并转录为 Markdown 格式；
- **音频录音**：调用 **Whisper 音频转写模型** 进行语音识别，自动输出带标点的文字文稿。

<Callout type="warning">
  若上传包含扫描图片或音频文件，请确保已在「项目设置 → Models」中成功配置了对应的多模态模型或音频转写模型，否则抽取阶段会由于缺少必要算力而标记为失败。
</Callout>

---

### 2. 文本清洗（Cleaning）
原始文档中常常混杂大量干扰字符，不仅占用向量数据库存储，还会对检索准确率产生负向影响。系统提供两种清洗级别：
- **`STANDARD`（推荐）**：
  - 自动归一化全角/半角字符；
  - 剔除无意义的控制字符、乱码与冗余空行；
  - 规范化 Markdown 标题与列表缩进；
- **`自定义规则`**：
  - 编写特定正则表达式，例如批量剥离企业合同中的免责声明页眉、机密水印文字或特定的系统生成标头。

---

### 3. 分块策略（Chunking）
分块决定了检索召回的细粒度与上下文完整度：

| 参数项 | 默认值 | 作用说明 | 调优建议 |
| ------ | ------ | -------- | -------- |
| **分块大小（Chunk Size）** | `1000` 字符 | 每个独立切块的最大字符上限 | 细颗粒度事实检索建议 `300–600`；长篇分析或大纲建议 `800–1200` |
| **分块重叠（Chunk Overlap）** | `200` 字符 | 相邻两个切块之间的重合字符窗口 | 建议设置为 Chunk Size 的 `15%–25%`，防止关键实体恰好处在分割点被截断 |

### 边界感知切分算法
系统并非生硬地按固定字符长度暴力切断，而是优先识别自然段落换行符（`\n\n`）、句子结束标点（`。`、`！`、`？`、`.`）作为分割点，尽可能保留语义单元的完整性。

---

### 4. 向量化与双路入库
切块完成后，系统将切块分批投递至向量化管道：
1. **Dense Vector（稠密向量）**：批量调用配置的 Embedding 模型（如 `text-embedding-3-small`），生成高维浮点向量存入 pgvector / Elasticsearch；
2. **Sparse Inverted Index（全文倒排索引）**：对切块进行分词并建立 BM25 索引，用于精确专有名词与型号的高效召回；
3. **状态翻转为「可用」**：两类索引就绪后，文档状态更新为绿色 `可用`，工作流和 MCP 即刻可检索到最新内容。
