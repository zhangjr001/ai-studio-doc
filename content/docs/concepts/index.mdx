理解这几个概念之间的关系，能帮你更快定位功能入口。

## 组织与项目

AI Studio 采用**组织 → 项目**两级结构：

- **组织（Organization）**：团队与权限的边界。成员在组织内拥有 `OWNER` / `ADMIN` / `MEMBER` 等角色，角色决定了能否管理成员、配置组织级模型等。
- **项目（Project）**：具体的工作空间。工作流、知识库、提示词等资源都归属在项目下；项目设置里可以管理通用信息与 **API Keys**。

一个组织可以包含多个项目；模型配置在组织与项目层级均可生效，项目级配置优先。

## 工作流

工作流是 AI Studio 的核心执行单元，由画布上的**节点**和节点间的**连线**组成一个有向流程：

- **开始节点**：接收用户输入或定时/外部触发；
- **处理节点**：LLM 调用、知识库检索、条件分支、工具/MCP 调用、HTTP 请求、代码执行等；
- **结束节点**：输出最终结果。

工作流支持**草稿编辑 / 发布版本**两个状态：编辑器中修改的是草稿，点击发布后对外提供服务的才是稳定版本。每次运行都会生成一条运行记录，便于回溯调试。

## 知识库

知识库把非结构化文档变成可检索的知识源，处理管线为：

```
上传文件 → 解析（PDF/Office/图片 OCR-VL、音频 Whisper 转写）
        → 清洗与分块（chunking）
        → 向量化（Embedding 模型）
        → 入库（向量 + 全文索引）
```

检索阶段支持向量相似度、全文匹配以及可选的 **Rerank 重排**，可按知识库分别配置。详见[知识库](/docs/knowledge)章节。

## 模型

模型管理按用途分为四类，统一在「模型管理」页面配置：

| 分类 | 用途 | 示例 |
| ---- | ---- | ---- |
| 对话模型 | LLM 节点、AI 构建、聊天 | GPT、Qwen、DeepSeek 等 |
| 嵌入模型 | 知识库向量化 | text-embedding、bge 系列 |
| 重排模型 | 检索结果二次排序 | bge-reranker 等 |
| 多模态模型 | 文档视觉解析、语音转写 | OCR-VL、Whisper |

只要兼容 OpenAI API 协议的推理服务（含 vLLM、Ollama 等本地部署）都可以接入。

## 提示词

提示词库提供可复用、可参数化的提示词模板，供工作流节点与聊天引用，支持在线调试与版本管理。

## 环境与配置

AI Studio 使用环境文件（`.env.development` / `.env.test` / `.env.production` 等）管理各环境的配置：数据库连接、JWT 密钥、模型网关地址等。关键密钥遵循 fail-closed 原则——缺失即拒绝启动。配置细节见[部署指南](/docs/deployment)。
