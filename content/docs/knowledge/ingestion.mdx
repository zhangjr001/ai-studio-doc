---
title: 上传与解析
description: 文档上传、解析管线、状态监控与失败排查
---

上传到知识库的每个文件都会经历一条异步解析管线。了解各阶段的行为，有助于排查「文档上传后检索不到」的问题。

## 上传文档

进入知识库详情页，点击**上传文档**：

- 支持批量选择多个文件；
- 上传完成后文档进入 `待解析` 状态，管线自动开始处理；
- 解析过程异步执行，大文件或多任务时会排队。

## 解析管线

```
文件上传 → 格式识别 → 内容抽取 → 清洗 → 分块 → 向量化 → 索引就绪
```

各阶段说明：

| 阶段 | 行为 | 常见失败原因 |
| ---- | ---- | ------------ |
| 格式识别 | 按扩展名与文件头识别类型 | 文件损坏、扩展名伪装 |
| 内容抽取 | 文本直取；图片走 OCR-VL；音频走 Whisper | 多模态模型未配置或服务不可用 |
| 清洗 | 去除页眉页脚、乱码、冗余空白 | - |
| 分块 | 按策略切分为 chunk（见下节） | 分块参数过小导致块数爆炸 |
| 向量化 | 调用嵌入模型生成向量并写入索引 | 嵌入模型额度耗尽、维度不匹配 |

## 分块策略

新建或编辑知识库时可选择分块策略：

- **固定长度**：按 token 数切分，适合绝大多数场景；
- **按段落 / 标题层级**：保留文档结构，适合结构清晰的 Markdown、Word；
- **重叠窗口**：相邻块保留一定重叠，减少语义被切断的损失。

<Callout type="tip">
  经验值：中文文档 chunk 大小 300–800 token、重叠 10%–20% 是不错的起点。检索效果不佳时优先调整分块参数，而不是换模型。
</Callout>

## 状态与排查

文档列表实时显示每个文档的处理状态（待解析 / 解析中 / 已就绪 / 失败）。失败文档会附带阶段与错误信息：

1. **多模态相关失败**：到「模型管理」确认 OCR-VL / Whisper 模型已配置且可访问；
2. **向量化失败**：检查嵌入模型 API Key 额度，以及向量维度是否与知识库初始设置一致；
3. **修复后**：在文档操作菜单中选择**重新解析**。

<Callout type="warning">
  嵌入模型一旦写入向量，更换模型会导致维度不一致。需要更换时，请新建知识库并重新上传文档。
</Callout>
