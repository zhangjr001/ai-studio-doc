Spark AI Studio 专为企业私有化部署量身打造，支持轻量级单机 Docker Compose 交付，也支持面向高可用生产集群的微服务拆分部署。

![项目 API Keys 访问密钥管理](/images/settings/api-keys.png)

## 一、系统架构与组件拓扑

| 服务组件 | 源码目录 / 技术栈 | 默认端口 | 职责说明 |
| -------- | ----------------- | -------- | -------- |
| **`web`** | `apps/web` (Vite + React 19 + Tailwind CSS) | `5173` | 可视化编排控制台、画布编辑器与用户界面 |
| **`api`** | `apps/api` (Spring Boot 3 + Maven 3.9+) | `8081` | 统一后端 API 服务，包含平台管理与工作流编排引擎 |
| **`kb`** | `apps/api/kb` (已集成至统一 Spring Boot API) | - | 知识库文档解析、多模态抽取、切块与向量入库管线 |
| **`postgres`** | PostgreSQL 15+ (含 pgvector 扩展) | `5432` | 存储多租户、用户身份、工作流 DSL、切块数据与向量索引 |
| **`minio`** | MinIO 对象存储服务 | `9000` | 存储上传的原始 PDF、Office 文档、图片与音频文件 |
| **`elasticsearch`** | Elasticsearch 8+ (可选) | `9200` | 高并发场景下的倒排索引与混合检索加速引擎 |

<Callout type="info">
  **知识库服务已完成架构合并**：新版本中 Knowledge / KB Pipeline 已完全嵌入统一的 Spring Boot API 中，无需单独启动旧版的独立 8088 进程。
</Callout>

## 二、生产环境配置与 fail-closed 安全机制

平台配置遵循严格的 **fail-closed（安全闭合/故障自锁）** 原则：关键配置缺失或使用不安全占位符时，后端服务将主动拒绝启动并打印明确报错，杜绝因疏忽带弱密码上线。

### 核心配置文件 `.env.local`
首次部署前从模板复制环境文件：

```bash
cp .env.example .env.local
```

修改其中的核心参数：

```ini title=".env.local 核心配置示例"
# 1. 数据库配置（禁止使用默认占位值 change-me）
SPRING_DATASOURCE_URL=jdbc:postgresql://9.72.192.123:30432/pgdb?currentSchema=ai_studio
SPRING_DATASOURCE_USERNAME=pguser
SPRING_DATASOURCE_PASSWORD=YourRealStrongPassword123!

# 2. JWT 签名密钥（必须为高强度随机字符串）
AGENT_FLOW_JWT_SECRET=c3BlY2lhbC1zdHJvbmctand0LXJhbmRvbS1zZWNyZXQta2V5LTIwMjY=

# 3. MinIO 对象存储
MINIO_ENDPOINT=http://minio:9000
MINIO_ACCESS_KEY=minioadmin
MINIO_SECRET_KEY=YourMinioSecretKey!

# 4. 可选：默认模型与网关地址
DEFAULT_OPENAI_BASE_URL=https://api.openai.com/v1
DEFAULT_OPENAI_API_KEY=sk-proj-xxxxxxxx
```

## 三、Docker Compose 一键启动

在项目根目录下执行：

```bash title="使用 Docker Compose 启动"
docker compose --env-file .env.local up -d
```

启动完成后检查容器健康状态：

```bash
docker compose ps
curl -s http://localhost:8081/actuator/health
```

## 四、本地开发模式（前后端分离）

如需对平台源码进行二次开发，可分别启动后端与前端：

### 1. 启动后端 API（JDK 17 + Maven 3.9+）
```bash
# 1. 导出环境变量
set -a
source .env.local
set +a

# 2. 进入后端应用目录并启动
cd apps/api
mvn spring-boot:run -pl platform-app
```

后端服务将在 `http://localhost:8081` 监听就绪。

### 2. 启动前端控制台（Node 20+）
```bash
cd apps/web
pnpm install
pnpm dev
```

前端开发服务器将在 `http://localhost:5173` 启动，支持代码修改热更新（HMR）。

## 五、项目对外访问控制 (API Keys)

业务系统如需集成 AI Studio 中发布的工作流，需在项目设置中申请项目级 API 密钥：

![项目设置基本信息与 API Keys](/images/settings/project-general.png)

1. 进入「项目设置 → API Keys」；
2. 点击 **+ New API Key**，输入密钥名称与过期时间；
3. 系统生成以 `sk-proj-` 开头的 Bearer Token，**该密钥仅在创建时完整展示一次**，请妥善复制保存；
4. 外部系统携带该 Token 调用公开执行端点：

```text
POST /api/v1/{project-slug}/workflows/{workflow-slug}/run
Authorization: Bearer sk-proj-xxxxxxxxxxxxxxxx
```
