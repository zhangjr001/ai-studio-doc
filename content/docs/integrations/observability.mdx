工作流从实验走向生产，最关键的挑战在于「黑盒可解释性」与「质量成本监控」。Spark AI Studio 原生集成了业界领先的开源 LLM 观测分析平台 **Langfuse** 与 **OpenTelemetry (OTel)** 规范，为每一个项目提供企业级全链路监控。

![项目 Observability 选项卡配置面板](/images/settings/observability-langfuse.png)

## 一、配置项目级 Langfuse 实例

进入「项目设置 → Observability」页面，勾选 **Send traces to Langfuse**：

1. **Host（服务地址）**：
   - 私有化部署填入内网地址（如 `http://9.72.192.123:3000`）；
   - 使用 SaaS 版本填入 Langfuse 官方地址（如 `https://cloud.langfuse.com`）；
2. **Public Key**：填写项目在 Langfuse 中生成的公钥（以 `pk-lf-` 开头）；
3. **Langfuse Project ID**：填写对应项目的唯一 ID，用于前端生成直达该项目 Trace 详情的 Deep-link 网页链接；
4. **Secret Key（安全保密）**：
   - 填写 Langfuse 私钥凭据；
   - **银行级落库加密**：在数据库底层采用 **AES-256-GCM** 高强度对称算法加密存储，前端 API 永远不会明文下发该密钥，确保凭据绝对安全。

## 二、工作流引擎 OpenTelemetry 追踪机制

后端执行引擎在 DAG 节点流转的每一个关键节点上都植入了标准 OpenTelemetry Spans：

```
[Workflow Run Root Trace]
  ├── [Start Node Span] ── 收集初始输入参数 (0.2ms)
  ├── [Rule Guardrail Span] ── 正则/PII/注入检测 (1.1ms, result=PASS)
  ├── [Agent Execution Span] ── 智能体调度总耗时 (1.4s)
  │     ├── [Prompt Template Interpolation] ── 参数填充与装配 (0.5ms)
  │     ├── [LLM API Call] ── 真实模型推理与流式接收 (1.1s, 240 tokens)
  │     └── [MCP Tool Execution Span] ── 知识库检索回调 (210ms)
  └── [End Node Span] ── 汇总最终输出数据 (0.3ms)
```

### 追踪与审计指标
- **Token 消耗精准核算**：按模型细分 Input Tokens、Output Tokens 与成本花费；
- **首字延迟（TTFT）与端到端耗时**：精确分析每一跳节点的延时瓶颈；
- **提示词与输出全景快照**：完整记录传递给模型的 Raw Prompt、变量插值上下文与模型实际输出，便于重现 Bad Case；
- **护栏判定审计**：记录输入是否命中 PII 规则或提示词注入特征，以及拦截原因。

## 三、实时调试中的一键 Trace 直达

在工作流编辑器的运行抽屉中，每一次发起交互式对话后，顶栏均提供了一键跳转的直达链接：

![实时调试抽屉中的 Langfuse 快捷入口](/images/workflow/run-and-debug.png)

点击顶部的 **↗ Langfuse** 按钮，浏览器将自动携带当前的会话 Trace ID 打开 Langfuse 监控控制台，直接定位到该次调用的执行树与调用栈。开发者无需在海量日志中检索 Session ID，便能秒级完成异常诊断。
