工作流（Workflow）是 Spark AI Studio 中将多个大语言模型、安全护栏、业务工具与条件分支串联成高可用生产应用的图形化编排引擎。

![工作流列表界面](/images/workflow/workflows-list.png)

## 画布操作与布局

进入工作流编辑器后，界面由顶栏工具、上方节点工具条、中央可视化画布、底部导航控制器以及右侧属性/调试抽屉组成：

![可视化工作流画布概览](/images/workflow/canvas-overview.png)

- **顶栏功能区**：
  - **状态徽标**：显示当前为 `草稿` 还是 `已发布 vX`；
  - **发布按钮**：将当前画布配置固化为不可变版本并上线生效；
  - **AI 构建助手（Sparkles 图标）**：唤起自然语言工作流生成器；
  - **自动整理（Layout 图标）**：对画布上的杂乱节点按照 DAG 执行流向进行整齐重排；
  - **DSL 代码查看（`<>` 图标）**：查看或复制工作流底层的标准 JSON DSL；
  - **导出按钮**：导出工作流定义文件。
- **节点工具条（Drag to canvas）**：
  - `CONTROL`：**Start**（开始）、**End**（结束）、**Router**（路由分支）；
  - `AI`：**Agent**（智能体核心节点）；
  - `SAFETY`：**Rule guardrail**（规则护栏）、**LLM guardrail**（语义护栏）。
- **左下角微调控制**：画布缩放（`+` / `-`）、自适应全屏对齐（Fit View）以及画布锁定。
- **右下角鹰眼（Minimap）**：大型工作流全局快速定位导航。

## 节点体系与配置参数

### 1. 开始节点 (Start)
作为工作流的输入源，定义外部调用该工作流时必须或可选传入的入参契约：

![Start 节点配置面板](/images/workflow/start-node-config.png)

- **输入变量定义（Inputs）**：
  - **变量名**：下游节点引用的标识（如 `input`、`query`、`user_id` 等）；
  - **数据类型**：支持 `string`、`number`、`boolean`、`object`、`array`；
  - **必填项勾选**：标记该输入是否为强制校验项；
  - **描述说明**：用于提示 API 调用方或在测试运行抽屉中作为占位提示。

---

### 2. 智能体节点 (Agent)
智能体是工作流中最核心的处理节点，封装了大模型推理、工具挂载、提示词组装与上下文记忆管理：

![Agent 智能体节点配置面板](/images/workflow/agent-node-config.png)

- **基本描述**：说明该 Agent 的职责（例如 `知识检索问答助手`）；
- **模型选择（Model）**：在下拉框中选择当前项目已接入的对话模型（如 `gemini-3.5-flash`），点击齿轮图标可进一步微调 Temperature、Top-P 等推理超参；
- **工具挂载（Tools）**：从项目内置的知识库 MCP 工具（如 `kb_xxx_HYBRID`、`kb_xxx_KNN`）或外部注册的 MCP 工具中勾选，模型会在推理时根据意图自主触发函数调用（Function Calling）；
- **会话记忆（Memory）**：
  - `关闭`：单次无状态问答，仅根据当前输入和上下文推理；
  - `会话`：开启多轮历史记忆，自动在对话中保留上下文连贯性；
- **系统提示词（System Prompt）**：
  - 既支持直接绑定项目提示词库中的模板（展示为带 Slug 如 `pmt_dt4l` 的标签，可一键点击 `Edit` 跳转或 `Unbind` 解绑）；
  - 也支持在节点内自定义内联提示词；
- **输入映射（Inputs）**：将上游节点的输出绑定到 Agent 所需的变量，如 `query <- Workflow input.input` 或 `query <- 上游分类.answer`；
- **输出格式（Outputs）**：
  - `纯文本`：模型直接输出字符串；
  - `结构化`：定义 JSON 字段契约（如 `answer: string`、`intent: string`），引擎强制模型按规范返回结构化对象。

---

### 3. 规则安全护栏节点 (Rule Guardrail)
专为企业安全合规打造的确定性前置/后置过滤节点，纯规则运算，零延迟且无 LLM 额外消耗：

![规则护栏配置面板](/images/workflow/rule-guardrail-config.png)

- **输入源（Input）**：默认接收 `Upstream output (default)` 或指定特定变量；
- **长度校验**：限制最大字符长度（例如 `2000`），超长直接阻断；
- **PII 隐私数据脱敏检测**：一键开启对敏感个人隐私的检测与拦截：
  - 中国大陆手机号
  - 居民身份证号
  - 机动车号牌
  - 车辆识别代号（VIN 车架号）
  - 电子邮箱地址
- **提示词注入与越狱防御（Prompt Injection）**：内置对抗常见越狱模式（如 Ignore previous instructions、扮演系统管理员等）的防御规则；
- **自定义正则表达式**：企业可自由添加专有敏感词、内部工号、商业机密关键词的正则规则；
- **双分支流转端口**：
  - `pass`（右侧蓝色端点）：安全校验通过，流程继续向下游流转；
  - `fail`（下方红色端点）：触发拦截规则，可连接独立的降级回复或结束节点。

---

### 4. 条件路由节点 (Router)
基于上游节点的执行产物进行智能条件分流：

![Router 路由分支配置面板](/images/workflow/router-node-config.png)

- **路由依据（Route On）**：
  - **来源节点**：选择上游决策节点（例如 `分类 (agent)`）；
  - **字段选择**：指定用于判定的字段（例如 `answer`）；
  - **表达式解析**：系统自动生成标准表达式，如 `{{ node.agent-1792653260062.output.answer }}`；
  - **高级模式**：支持勾选「使用原始表达式」，编写复杂的逻辑计算；
- **分支映射（Branches）**：根据取值动态连接不同下游节点，例如：
  - 值为 `汽车` 时导流至 `汽车知识问答Agent`；
  - 值为 `其他` 时导流至 `通用问题回答Agent`。

---

### 5. 模型语义护栏节点 (LLM Guardrail)
对于规则无法完全覆盖的复杂语义判定，使用轻量化大模型进行安全审校：
- **判定提示词（Judge Prompt）**：配置判定准则（如越权越狱、闲聊寒暄、辱骂有害等）；
- **输出端口**：同样具备 `pass` 与 `fail` 两个出口，灵活实现不同场景的动态干预。

## 编排实战：9节点多智能体分类问答系统

在复杂生产实践中，通常会将安全防护、意图分流与领域垂直智能体结合使用。以下为平台实机编排案例：

![9节点多智能体复杂编排实战](/images/workflow/complex-orchestration.png)

### 拓扑链路解析

1. **Start 节点**：接收用户发起的咨询输入；
2. **Rule Guardrail 节点**：
   - 过滤输入长度（不超过 2000 字）；
   - 执行 PII 隐私扫描（拦截手机号、身份证号等）；
   - 执行提示词注入扫描；
   - **拦截分支（fail）**：直接接入终止节点并输出拒绝说明；
   - **通过分支（pass）**：放行至意图分类智能体；
3. **分类 Agent**：
   - 采用轻量快速模型（如 `gemini-3.5-flash`）；
   - 绑定专用提示词 `pmt_7onp`，将用户提问归类为「汽车」或「其他」；
4. **Router 节点**：
   - 解析分类 Agent 的输出字段 `answer`；
   - 命中 `汽车` 分支：流向挂载了企业车书知识库工具的 `汽车知识问答Agent`；
   - 命中 `其他` 分支：流向用于日常闲聊或兜底的 `通用问题回答Agent`；
5. **智能体挂载工具执行**：
   - 汽车知识问答 Agent 具备 `1 tool selected`（即知识库检索工具），通过精确召回车书规范回答细节问题；
6. **End 节点**：收集最终生成内容向客户端完成响应。

![智能体工具挂载细节](/images/workflow/agent-with-tools.png)

## 连线规则与变量传递

1. **类型兼容**：从输出端口拖拽至输入端口时，系统会自动进行连接校验；
2. **唯一与多路连接**：
   - 普通节点的输入端口支持连接单个上游节点；
   - Router 和 Guardrail 的输出端口可针对不同分支连接不同目标节点；
3. **上下文变量穿透**：工作流执行过程中，所有上游节点的输出数据都会作为不可变上下文字典向下传递，任何下游节点均可通过 `{{ node.<node_id>.output.<field> }}` 规范引用。
