面对复杂的业务场景，从零在空白画布上手动拖拽节点、连线与配置参数往往需要大量尝试。Spark AI Studio 内置了工业级的 **AI 构建助手（AI Builder）**，采用自然语言生成（NL→Workflow DSL）与多轮自愈重试机制，只需一句话描述业务意图，即可全自动生成结构合规、可直接调试的工作流初稿。

---

## 一、唤起途径与交互面板

AI 构建助手深度融入工作流的整个生命周期，支持在多种场景下一键唤起：

1. **工作流新建默认引导**：在项目工作流列表页点击「从空白画布开始编排」后，系统自动打开编辑器并携带 `?builder=1` 参数，首屏即在右侧展开 AI 构建面板；
2. **画布顶栏随时唤起**：在画布任意编辑过程中，点击顶栏工具栏的 **Sparkles 图标（AI 构建）**，右侧随时滑出交互面板；
3. **空白画布引导按钮**：当画布处于初始空状态时，中央引导卡片提供「AI 构建」快捷按钮。

![AI 构建交互面板与模型选择](/images/workflow/04-ai-builder-chat.png)

### 交互面板核心区域

- **会话历史流（Chat Bubbles）**：记录用户输入的自然语言描述与 AI 助手的设计回复；
- **生成模型选择器**：下拉菜单支持选择用于生成该工作流的底层推理模型（默认自动选用当前项目已启用的通用 CHAT 模型，例如 `gemini-3.5-flash`，也可按需切换）；
- **快捷架构模板 Chips**：提供高频的企业级拓扑脚手架，点击即可将模板描述预填入输入框：
  - **单个智能体（Single agent）**：`做一个客服助手，直接回答用户的问题。`
  - **带护栏（Guarded）**：`先检查用户输入是否包含敏感词，通过后由客服助手回答；被拦截时给出友好提示。`
  - **按意图分流（Intent router）**：`按意图分流处理客服问题，意图包括：退款、咨询、投诉，其他走默认分支。`
- **自然语言输入区**：支持输入最长 2000 字符的自由业务需求描述。

## 二、后端技术实现：自愈生成闭环

工作流生成不是简单的文本输出，而是必须生成符合 Spark AI Studio 强类型 DSL 规范、图拓扑无环且逻辑闭环的 JSON 结构。为此，系统在后端构建了兼顾**防幻觉**与**多轮自愈重试**的可靠性架构。

```
[前端提交 NL 描述] ──► POST /api/workflows/generate
                                │
                      注入项目已配置的 CHAT 模型清单
                                │
                                ▼
                       ┌─────────────────┐
                       │  调用大语言模型  │ ◄────────────────┐
                       └────────┬────────┘                  │
                                │ 提取 Explanation 与 JSON   │ (≤ 3 次自愈重试)
                                ▼                           │
                       ┌─────────────────┐                  │
                       │ 校验模型 ID 合法 │                  │
                       └────────┬────────┘                  │
                                │ sanitizeModelIds          │
                                ▼                           │
                       ┌─────────────────┐                  │
                       │ WorkflowGraph-  │ 校验失败(硬错误) │
                       │    Validator    ├──────────────────┘
                       └────────┬────────┘ (将校验错误附加为反馈信息)
                                │ 校验通过
                                ▼
              返回 GenerateWorkflowResponse (图结构 + 设计说明)
```

### 1. 接口契约规范 (`POST /api/workflows/generate`)

```typescript
export interface GenerateWorkflowRequest {
  projectId: string;
  /** 自然语言需求描述(1..2000 字符) */
  prompt: string;
  /** 生成所用模型 UUID; null = 项目已配置 CHAT 清单第一项 */
  modelId?: string | null;
}

export interface GenerateWorkflowResponse {
  /** 经后端结构校验 + modelId 核验后的 WorkflowDsl JSON */
  graphJson: string;
  /** LLM 的一句话设计说明 */
  explanation: string;
  /** 实际 LLM 调用次数(1..3),含校验失败后的修复重试 */
  attemptsUsed: number;
}
```

### 2. 抑制模型幻觉 (Anti-Hallucination)
大模型在生成 JSON 时极易自行捏造随机的 `modelId`。系统在构建 System Prompt 时，会自动动态注入目标项目内真实已启用的模型清单（包含 UUID 与模型名称）；生成后，后端服务（`WorkflowGenerationService`）会严格比对 UUID，将不存在的无效值置空或重写，防止因模型 ID 悬空导致图校验崩溃。

### 3. 多轮自愈重试机制 (Self-Healing Loop)
系统设定了最大 3 次调用重试上限（`MAX_ATTEMPTS = 3`）：
- **硬结构错误拦截**：若模型输出的 JSON 存在语法错误、节点断连、缺少 Start/End、连线方向非法等硬性结构问题，`WorkflowGraphValidator` 会捕获详细的校验报错；
- **错误动态回喂**：系统自动将具体的报错条目（如 `Agent 节点 [agent-1] 缺少指向 End 节点的输出连线`）拼接为下一轮提示词反馈，要求大语言模型针对性修复；
- **软配置放行**：对于未选定具体模型等预期缺口，系统予以放行，留待用户落到画布后再进行精细化调整。

## 三、结果预览与安全替换机制

大模型生成完成后，前端不会直接粗暴地覆写画布，而是呈现透明清晰的审查与确认机制：

![AI 构建生成结果预览](/images/workflow/05-ai-builder-generated.png)

1. **设计思路阐释**：对话流中展示 AI 针对该需求的设计总结（例如：*使用规则护栏过滤敏感词，通过分支接入客服助手解答，拦截分支接入提示节点给出友好回复*）；
2. **生成结果预览徽章**：清晰统计并展示拓扑节点分布（例如：`START ×1、RULE_GUARDRAIL ×1、AGENT ×2、END ×2`）；
3. **安全覆盖二次确认**：
   - 点击 **「生成到画布」**；
   - 系统检测到当前画布已存在未保存或已有节点时，弹出高危确认弹窗，明确提示 *「画布上已有节点，生成的工作流会覆盖它们，此操作不可撤销」*；
   - 用户点击 **「替换」** 后才正式写入画布全局 Store。

![AI 构建生成到画布确认对话框](/images/workflow/06-ai-builder-confirm.png)

## 四、落地画布后的拓扑转换与自动排版

当生成的 DSL 写入画布时，前端转换引擎会自动处理布局与连线容量细节：

### 1. 智能端口容量分配 (`toEdges`)
大语言模型通常无法精确知晓每个节点物理端口的方向（如 `left`、`right`、`pass`、`fail`）以及端口最大容纳的连线数。前端 `toEdges` 模块会根据节点注册表（`nodeRegistry`）的端口定义，自动将汇入边连接到尚未满容的输入方向，将 Guardrail 节点的不同出口正确分派至 `pass` 与 `fail` 端口。

### 2. 自动对齐排版 (`applyAutoLayout`)
落入画布的瞬间，系统自动调用基于 Dagre 算法的 **LR（从左至右）** 拓扑自动排布引擎，自动计算所有节点的高宽与连线曲率，生成对称、工整、易于阅读的编排全景图。

### 3. 与人工编辑无缝共存
AI 生成的工作流**绝不直接写入数据库持久层**，而是作为编辑器的临时草稿状态。开发者可以像对待手动搭建的工作流一样：
- 拖拽调整节点间距与走线；
- 点击智能体节点切换模型参数或挂载企业知识库工具；
- 编写测试用例并在右侧「运行与测试」面板进行断点调试；
- 验证满意后点击右上角的 **「发布」** 按钮，生成线上生效版本。
