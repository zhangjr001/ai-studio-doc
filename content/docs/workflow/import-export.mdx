在多团队协同与敏捷迭代过程中，工作流（Workflow）不仅仅是一张静态的 DAG 画布，更是汇集了业务拓扑、安全护栏、模型参数以及精调 Prompt 的综合资产。

为了满足**开发/测试/生产跨环境迁移**、**团队间工作流模板共享**以及**离线版本备份**的业务诉求，Spark AI Studio 提供了工业级的工作流导入与导出能力，支持自包含的信封格式协议与智能资源重连。

---

## 一、操作入口与交互流转

系统在**工作流列表页**与**画布编辑器顶栏**均提供了直观的操作入口。

### 1. 工作流列表页操作

在项目工作流列表页（`/project/:id/workflows`）中：

![工作流列表页导入与导出入口](/images/workflow/01-workflow-list-transfer.png)

- **导入工作流**：在首张「从空白画布开始编排」引导卡片中，提供次级动作 **「导入（从 .workflow.json 文件）」**，点击即可唤起导入对话框。
- **导出单条工作流**：在已有的工作流卡片（如「知识问答（分类-汽车-其他）」）右上角，点击 **下载图标（导出工作流）**，浏览器将立即下载最新保存的自包含配置文件。

### 2. 画布编辑器顶栏操作

在工作流画布编辑器（`/project/:id/workflows/:id/edit`）内编排时，顶栏右侧工具区同样集成了导入与导出功能：

![画布编辑器顶栏导入导出入口](/images/workflow/03-workflow-canvas-export.png)

- **导出**：点击顶栏的 **下载图标**，即可将当前画布上已保存的工作流配置导出为 `.workflow.json` 文件。
- **导入**：点击顶栏的 **上传图标**，支持在当前编辑器中直接导入外部文件；若当前画布存在已编辑内容，系统在导入前会提示二次确认，避免误操作覆盖。

### 3. 导入对话框与即时预检

点击「导入」后，系统弹出专属的工作流导入对话框：

![工作流导入对话框与即时预检](/images/workflow/02-workflow-import-dialog.png)

- **格式与拖拽支持**：支持拖拽或点击选择 `.workflow.json`（兼容裸 DSL JSON）。
- **客户端即时预检与统计**：
  - 选定文件后，前端立即完成 JSON 格式与协议校验；
  - 实时提炼并展示拓扑统计：**节点数**、**连线数**、**全局变量数**以及**携带提示词的节点数**；
- **元数据快速调整**：支持在导入落库前直接修改**工作流名称**、**描述**以及查看关联的标签信息；
- **错误即时反馈**：若文件损坏或超出大小限制（最大 2MB），系统将直接高亮提示具体原因。

## 二、自包含信封协议规范 (Envelope v1)

为了保证工作流在脱离当前数据库上下文后依然具备完整的可读性与可恢复性，Spark AI Studio 采用了自包含的 **信封格式协议（Envelope Specification v1）**。

### 1. 信封协议结构解析

导出的 `.workflow.json` 文件由四个核心层级构成：

```json title="知识问答（分类-汽车-其他）.workflow.json"
{
  "format": "ai-studio-workflow",
  "version": 1,
  "exportedAt": "2026-11-19T06:47:36.460430Z",
  "source": {
    "workflowId": "372730d5-f4fb-4479-a0d4-fca73b70b456",
    "slug": "untitled-2"
  },
  "workflow": {
    "name": "知识问答（分类-汽车-其他）",
    "description": "多意图分流与汽车垂直领域知识库问答编排",
    "tags": ["汽车咨询", "多分支路由"]
  },
  "graph": {
    "dslVersion": "1.0",
    "nodes": [ ... ],
    "edges": [ ... ],
    "globals": [ ... ]
  }
}
```

| 字段层级 | 字段名 | 类型 | 说明 |
| -------- | ------ | ---- | ---- |
| **协议头** | `format` | string | 固定为 `"ai-studio-workflow"`，作为文件身份标识。 |
| | `version` | number | 当前信封契约版本，目前为 `1`。 |
| | `exportedAt` | string | ISO-8601 格式的导出时间戳。 |
| **源追溯** | `source` | object | 记录导出源工作流的 `workflowId` 与 `slug`，便于版本审计。 |
| **元数据** | `workflow` | object | 包含工作流名称（`name`）、描述（`description`）与标签（`tags`）。 |
| **拓扑主体** | `graph` | object | 完整的 DAG 结构，包含 `nodes`（节点）、`edges`（边）与 `globals`（全局变量）。 |

### 2. 文件命名与中文兼容规范

- 默认文件名格式为 `{name}.workflow.json`；
- 文件名中若包含操作系统非法字符（如 `\`、`/`、`:`、`*`、`?`、`"` 等），系统会自动转义替换为下划线 `_`；
- 后端在响应头中严格使用 **RFC 5987** 规范（`Content-Disposition: attachment; filename*=UTF-8''...`），百分号编码下发文件名，确保各类浏览器下载中文名称工作流时均不会出现乱码。

### 3. 向后兼容机制

系统具备良好的向下兼容性：若导入的内容未包含 `ai-studio-workflow` 信封结构，但顶层包含合法的 `nodes` 与 `edges` 数组（例如历史旧版本导出的裸 DSL 或直接从数据库复制的 `graphJson`），导入解析器会自动将其包裹一层默认元数据信封无缝入库。

## 三、核心技术机制：提示词水合与解耦

在复杂的智能体系统中，提示词通常既属于工作流，又可作为企业级 Prompt 资产在资产库中被多个智能体跨流复用。如何处理导入导出时的提示词依赖，是资产迁移的核心挑战。

### 1. 导出时正文水合 (Prompt Hydration)
- **底层现状**：在工作流日常保存落库时，系统底层拦截器会将 Agent 的系统提示词（`systemPrompt`）与语义护栏的判定词（`judgePrompt`）统一抽取为独立的 Prompt 实体资产，工作流的 `graphJson` 内仅保存关联的 `systemPromptId` 或 `judgePromptId`。
- **水合机制**：在执行导出操作时，`WorkflowTransferService` 会动态查询关联的 Prompt 最新正文，并将其完整回填写入各节点的 `config.systemPrompt` / `config.judgePrompt` 中（同时保留 ID）。
- **收益**：导出的 JSON 文件完全自包含，无需依赖远程数据库即可直接离线查阅或在本地代码库中评审。

### 2. 导入时独立解耦 (Prompt Decoupling)
- **解耦原则**：将工作流导入目标项目时，系统无条件剥离原始的 `promptId`，仅保留其正文内容；
- **独立副本生成**：底层服务在目标项目中针对每个携带提示词的节点调用 `createWithFirstVersion`，为目标项目自动创建全新的独立 Prompt 资产；
- **防污染保证**：导入后的新工作流在后续调整提示词时，绝不会反向污染源项目或其他已有工作流；若目标项目中存在重名提示词，系统会自动追加 `(2)`、`(3)` 等后缀以示隔离。

## 四、核心技术机制：模型与工具智能重连

在跨项目、跨团队甚至跨私有云环境迁移工作流时，不同项目中的模型接入凭证（`modelId`）和 MCP 服务凭证（`mcpServerId`）具有不同的 UUID。如果机械还原，将导致所有节点抛出「资源不存在」的致命错误。

Spark AI Studio 设计了**「名称匹配 + 智能重连」**管道：

```
[导出的自包含文件] (包含 modelName / mcpServerNames)
         │
         ▼
[导入解析与重连器]
         │
         ├─► 1. 目标项目精准命中相同 UUID? ──► [保留原有绑定 (同项目导入幂等)]
         │
         ├─► 2. UUID 失配但模型名称匹配? ────► [自动重写为目标项目的对应模型 ID]
         │
         └─► 3. 完全无可用匹配? ────────────► [保留字段满足硬校验 + 画布高亮待选]
```

### 1. 导出阶段：元数据辅助水合
导出时，系统自动为每个关联的模型附加 `modelName`（如 `gemini-3.5-flash`、`gpt-4o` 等前端下拉展示名称）；为挂载的 MCP 工具附加 `mcpServerNames`（映射表：`serverId → displayName`）。

### 2. 导入阶段：自适应重写机制
1. **同项目重导入（幂等保障）**：若在同一项目内导入复制，由于 `modelId` 与 `serverId` 在当前项目中完全一致，系统原样保留该绑定；
2. **跨项目自动重连**：当 UUID 在目标项目中未命中时，系统自动根据 `modelName`（忽略英文大小写）检索目标项目中所有处于启用状态的同类型模型（如 CHAT），自动重写节点的 `modelId`；对 MCP 服务则依据 `displayName` 自动绑定目标项目的同名 Server；
3. **彻底失配兜底**：若目标项目完全没有同名模型，系统会保留该字段以保证通过图拓扑的硬性非空校验，并在进入画布后提示开发者在右侧属性面板重新选取可用模型。

## 五、安全与容量加固

1. **体积防御限制**：
   - 前端限制上传文件体积上限为 **2 MB**，超出后在浏览器端直接阻断并提示；
   - 后端统一限制 `MAX_GRAPH_LENGTH = 2,000,000` 字符，杜绝超大载荷对服务器内存与 JSON 解析器的拒绝服务（DoS）隐患。
2. **全流程图校验 (Graph Validation)**：
   - 导入数据在正式入库前，必须完整通过 `WorkflowGraphValidator` 结构校验；
   - 确保 DAG 拓扑满足：**单起点 Start**、**有效终点 End**、**无孤立环路** 以及 **合法的数据流连线方向**。
